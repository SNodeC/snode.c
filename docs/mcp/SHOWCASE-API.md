# MCP showcase API inventory

Baseline: `69b16419a`. Source inventory; execution results and native-client limitations are recorded in [QUALIFICATION.md](QUALIFICATION.md). Sampling and roots are opt-in operations, including their deprecated 2026 forms; see [client inputs](CLIENT-INPUTS.md). Every implemented public feature is demonstrated in the separate `snodec-mcp-showcase-*` applications; `snodec-mcp-client client --command tour` drives its public client APIs.

The invariant is one protocol implementation: the showcase consumes public MCP APIs and existing transport bindings; it must not implement a second MCP engine. Application state and timers live on the event loop and terminate with their request or server owner.

## Protocol operation inventory

This inventory distinguishes supported operations from operations removed in the other protocol era. Optional capabilities remain opt-in where application ownership is required. Native UI exposure is recorded independently in the qualification report.

| Operation group | 2025-11-25 | 2026-07-28 | Demonstration and automated boundary |
| --- | --- | --- | --- |
| Lifecycle | `initialize`, `notifications/initialized`, bidirectional `ping` | `server/discover`, per-request version/capabilities | Tour negotiation and legacy `server.ping`/`client.ping`; handshake and client unit tests |
| Tool inventory/execution | `tools/list`, `tools/call` | Same | Paged inventory, concrete tools, schemas, all content variants and deliberate errors; tour/wire/schema tests |
| Resources | `resources/list`, `resources/templates/list`, `resources/read` | Same | Text/blob/counter, URI templates, caching, pagination and dynamic registrations; tour/wire/resource tests |
| Prompts/completion | `prompts/list`, `prompts/get`, `completion/complete` | Same | Conversation, embedded content and contextual prompt/template completion; tour/wire tests |
| Notifications | Tool/resource/prompt list changes and resource updates; `resources/subscribe`, `resources/unsubscribe` | `subscriptions/listen`, acknowledgement and filtered changes/updates | Live add/remove, changed counter and subscription lifecycle; tour/wire/subscription tests |
| Work | `notifications/progress`, `notifications/cancelled` | Same, with request-scoped tokens | Progress, cancellation, deadline and timeout steps; context/client/tour tests |
| Elicitation | `elicitation/create`, optional URL completion notification, URL-required error | `elicitation/create` inside input continuations | Form/URL, multiple/parallel rounds, resource/prompt/task input, URL completion and required URL; tour/wire/input tests |
| Sampling | `sampling/createMessage`, tools/context capabilities and client-owned task augmentation | Same input operation in continuations; deprecated; no separate client-owned task RPC | Sampling text/image/audio, model options, tool choice and full tool loop; tour/wire/client-input tests |
| Roots | `roots/list`, optional `notifications/roots/list_changed` | `roots/list` in continuations; deprecated; no list-change notification | Fresh/changed roots, metadata, refusal and lifetime; tour/wire/client-input tests |
| Logging | `logging/setLevel`, `notifications/message` on the session | Per-request log-level metadata and `notifications/message` only on its originating response stream; deprecated | Logging tool, threshold/size/rate controls, opt-in and invalid-level controls; logging/tour/wire tests |
| Tasks | `tasks/get`, `tasks/list`, `tasks/result`, `tasks/cancel`, optional `notifications/tasks/status`; server-hosted tools and client-hosted sampling/elicitation | Negotiated tasks extension: `tasks/get`, `tasks/update`, `tasks/cancel`, `notifications/tasks` subscription | Optional/required tool tasks, task input/update, client task result/cancel, status/list, expiry and session isolation; task/client-input/tour/wire tests |
| HTTP/HTTPS | Authorization callback, protected-resource metadata, origin policy, sessions and replay | Authorization/metadata/origin policy and per-request routing; no legacy session replay | Both named transport instances, principal/header checks, replay retirement and clean shutdown; HTTP/TLS/component tests |

Application-owned model providers, consent UI, filesystem access and OAuth flows remain application responsibilities. The library carries their protocol requests, results, capabilities and authorization decisions; the deterministic showcase does not supply these external services.
